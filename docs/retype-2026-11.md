# Validation as re-typing: one 8-class model over label types (November 2026)

Experiment for [#13](https://github.com/ProjectSidewalk/sidewalk-validator-ai/issues/13). Five binary models answer
"is this a correct CurbRamp label?" and so on. One model that answers "what is in this crop?" over eight label types
could validate by checking the claimed type, name the right type when the label is wrong, and share features across
types, which should help the small ones. This page describes the experiment as built, the numbers measured before
training, and the result tables the report stage fills.

**Status: not yet run.** The code, the Slurm chain and the tests are in place
(`retype.py`, `fine_tune_retype.py`, `retype.slurm`, `retype_submit.sh`). No GPU job has run. Every number under
"Results" is a placeholder until the chain runs on klone. The numbers under "What was measured" are real and come
from [`retype-2026-11/audit.json`](retype-2026-11/audit.json).

## Why

- A share of crowd Disagree votes are type errors: the feature is real but it is a driveway, not a curb ramp, or a
  surface problem, not an obstacle. A binary model can only say "wrong"; a type model can say "wrong, and it is a
  NoCurbRamp".
- Project Sidewalk now lets a validator change a label's type
  ([SidewalkWebpage#3671](https://github.com/ProjectSidewalk/SidewalkWebpage/issues/3671)), and the platform asks
  the AI again after an edit. A suggested type is what that flow would show.
- Small classes may gain from a shared head. Crosswalk has 1,040 training positives in round 3. Signal and
  NoSidewalk have no model at all ([#42](https://github.com/ProjectSidewalk/sidewalk-validator-ai/issues/42)).

## What was measured (2026-11-05)

All from [`retype-2026-11/audit.json`](retype-2026-11/audit.json): the round-3 splits and rawLabels snapshot of
2026-10-19, and labelEdits exports pulled on 2026-11-05 from the 46 public deployments the live `/v3/api/cities`
listed. Private deployments are pooled.

**Type edits are almost nil.** The 46 labelEdits exports hold 13,274 edits. Four change the type, all by humans,
all in September and October 2026: CurbRamp to NoCurbRamp, NoCurbRamp to CurbRamp, CurbRamp to Other and
SurfaceProblem to Obstacle (cdmx 1, st-louis-mo 2, newport-ky 1). The rest are tag and severity edits. The type-edit
UI is new, so this source grows from now on. Today it gives no training signal and at most four evaluation labels.
With the job's default `EDIT_RAWLABELS` (the round-3 rawLabels snapshot of 2026-10-19) only two of the four join:
the other two edits are newer than the snapshot, so the label's type there is still the old one (`type_mismatch`).
All four join only with a fresh rawLabels pull (`EDIT_RAWLABELS=<fresh pull>`). The "suggested type" evaluation
therefore leans on the two other ground truths below.

**Colocated proxy.** An `incorrect` label of type A with a `correct` label of exactly one other type B within the
radius, placed by another user. Over the 26,618 crowd-incorrect labels of the eight classes in the 50 round-3
deployments:

| radius | labels with a proxy | top pairs (A → B) |
|---|---:|---|
| 1.5 m | 623 | NoCurbRamp → CurbRamp 211, CurbRamp → NoCurbRamp 62, SurfaceProblem → CurbRamp 52, CurbRamp → SurfaceProblem 45, Obstacle → CurbRamp 40 |
| 3 m | 1,214 | NoCurbRamp → CurbRamp 317, SurfaceProblem → CurbRamp 107, CurbRamp → SurfaceProblem 89, Obstacle → CurbRamp 83, CurbRamp → NoCurbRamp 81 |

It is a proxy. A wrong NoCurbRamp next to a correct CurbRamp may be a type error, or a second label on the same
corner. It is used for evaluation only, and every table that uses it says so.

**Cross-type panorama sharing is large.** Round 3 split each type on its own. Of the round-3 split rows, 21.6 %
(CurbRamp), 17.5 % (NoCurbRamp), 15.7 % (Obstacle), 16.0 % (SurfaceProblem) and 35.7 % (Crosswalk) sit on a
panorama that also holds a row of another type. A model trained on the union would see test panoramas in training
unless the splits are reconciled (see "Leakage").

**Data for the extra types** (eligible human-authored labels by the crowd margin rule, before downsampling):

| class | correct | incorrect | note |
|---|---:|---:|---|
| NoSidewalk | 88 | 139 | 227 of 358,905 NoSidewalk labels meet the margin rule; almost none are validated |
| Signal | 7,121 | 311 | |
| Other (Other + Occlusion) | 10 | 8 | below the 10-incorrect minimum: no crops, the class is only the "none of these" sink |

With `--correct-proportion 0.9` (the one hook this experiment adds to `data_generation.py`) the selection keeps up to
9 correct per incorrect, so Signal yields about 2,800 + 311 crops and NoSidewalk all 227. Without it (0.55) Signal
would keep about 380 correct.

## Method

### Classes

`retype.CLASSES` = CurbRamp, NoCurbRamp, Obstacle, SurfaceProblem, Crosswalk, NoSidewalk, Signal, Other (index 7).
The order is a serving contract (sidewalk-ai-api reads `config.json` `id2label` by index) and is pinned by
`tests/fixtures/retype/id2label.json`. Occlusion labels map to Other.

### Ground truth

| source | rows | claimed type | target type | used for |
|---|---|---|---|---|
| validated | every row of the round-3 `<Type>/split.csv`, plus the extra types | the label's type | the label's type if `correct`, empty if `incorrect` | train and evaluation |
| type edit | labelEdits rows with a new type, not by the SidewalkAI account, latest edit per label, joined to the label's current rawLabels row (its type must equal the new type) | the new type (correct) and the old type (incorrect), two rows per label | the new type | evaluation only, split `test_retype` |
| colocated (flag) | an incorrect validated row with a proxy type (above, 1.5 m) | the label's type | `proxy_type` = B | evaluation only |

**An incorrect row has no known true type.** The crowd said "not a CurbRamp", which says nothing about what it
is. So incorrect rows are not mapped to Other. They train through a complement loss on the claimed type:
`-log(1 - p(claimed))`. The model may put that mass on any other class, Other included (complementary-label
learning). It is computed exactly, as `logsumexp(all logits) - logsumexp(logits without the claimed one)`, so a
confidently wrong row keeps its full gradient however large the claimed logit gets. The alternative, "an incorrect
row is an Other positive", is the `other` leg, run as an ablation. In both legs a negative row has weight 1. The
class weights below apply to positives only, so a few Other positives cannot rescale every negative in the `other`
leg.

### Training (`fine_tune_retype.py`)

Round 3's recipe, unchanged except for the head and the loss: `facebook/dinov2-large`, batch 8 × accumulation 4,
lr 1e-5, warm-up 0.1, `RandomResizedCrop(224, scale=(0.7, 1.0))` and flip for train, the slow image processor for
val. 12 epochs (each epoch is about five times a round-3 type's). Positives are weighted per class by
`(mean count / class count) ^ 0.5`, clipped to [0.5, 4], renormalised to mean 1. The kept checkpoint maximises
`auc_claimed` on val: the AUC of `p(claimed)` for correct against incorrect per claimed type, averaged over the five
validator types and weighted by their val rows. That is the verdict the API would serve. The weighting keeps a type
with a few dozen val rows from moving the selection as much as CurbRamp. The extra types are reported per type but
do not select, since no deployed validator serves them. Resume after preemption works as in `fine_tune_classifier.py`; the run key holds
the split hash, the leg (`negatives`), the class-weight power and the cap.

### From eight probabilities to the served verdict

`p_correct = p(claimed type)`, `p_incorrect = 1 − p_correct`. `retype.py export-binary` writes each type's rows in
`evaluate.py`'s predictions format, so the unchanged `evaluate.py --skip-inference --tag retype-<leg> --per-city`
and `calibration/calibrate.py` score and calibrate the re-typing verdict per claimed type, under the same deployment
prior as that type's own model. `suggested_type` is the most probable class other than the claimed one.

## Leakage

Round 3 split each type independently by panorama (with a 3 m merge), so one panorama can be `train` for Obstacle
and `test` for CurbRamp. The multi-class split inherits round 3 and then resolves each panorama to the
highest-priority split any of its rows had: `test_heldout` > `test` > `val` > `train`.

- Every round-3 `test` and `test_heldout` row keeps its split. The comparison with the five round-3 models therefore
  runs on exactly round 3's test rows, and `report` refuses to compare if the row sets differ.
- The price: train and val rows of other types move up. On the round-3 splits 3,035 rows move: 1,348 train → test,
  1,395 train → val and 292 val → test, across the five types (`inherit_moves` in
  [`audit.json`](retype-2026-11/audit.json)). That is 2,743 of round 3's 42,267 train rows (6.5 %). Moved rows are
  left out of the per-type comparison: round 3 trained on the ones that came from train, and its checkpoint
  selection saw the ones that came from val.
- The extra types are split by `split_data.py` with round 3's held-out cities and seed, then reconciled the same way.
- **Known gap.** Round 3 does not record its 3 m merged groups, so a corner seen from two different panoramas can
  still be train for one type and test for another. `assemble --merge-radius-m 3` reruns the merge on the union
  (off by default; a follow-up).
- Type-edit labels already in a round-3 split are dropped from `test_retype` (they were trained under their old
  type). Their panoramas may still appear in train; `assemble.json` counts them (`on_train_or_val_pano`).

`gate_what_if.csv`: for each type, a map fitted on val under the deployment prior, for the retype verdict and for

`type_head.csv` and `confusion_correct_test.csv`: top-1 and top-3 accuracy of the type head on correct rows, per

labels are, per claimed type.

### Suggested type

- Type edits (`type_edit_eval.csv`): top-1 and top-3 of the suggestion against the human's new type. n = 4 today,
  and fewer if a label's crop or current row is missing. Read it as a smoke test, not a measurement.
- Colocated proxy (`colocated_eval.csv`): the same against `proxy_type`, per split. A proxy, as above. It also has
  a location leak. B, the correct label that makes the proxy, is often on another panorama than A, and that
  panorama can be in train. The model has then seen B's crop as a B positive, so "suggested = B" may be a memorised
  place. On the round-3 data at 1.5 m, 455 of the 623 proxies have B on another panorama, and 264 have B's
  panorama in train after inheritance. Among the eval rows that is 37 of 129 test rows and 29 of 106 val rows.
  `test_heldout` has none: its cities have no train rows, and colocation never crosses cities. `assemble` records
  the flag per row (`proxy_b_in_train`) and `colocated_eval.csv` breaks every split down by it (`all`, `0`, `1`).
  The headline is `test_heldout`; on `test` read the `0` rows.

## API contract (proposed)

The request is unchanged: `label_type` stays the claimed type. A retype model adds three response fields:

- `type_probabilities`: `{class: p}` over the model's `id2label`, eight keys.
- `suggested_label_type`: the most probable class other than the claimed one and other than Other; `null` when
  Other beats it, or when `validation_result` is `correct`.
- `suggested_label_type_confidence`: that probability, `null` with it.

`validation_result` and `validation_score` keep the existing argmax rule on `p_correct = p(claimed)` and
`p_incorrect = 1 − p_correct`, and the per-type `accuracy_mappings/<type>.json` lookup is unchanged, so
SidewalkWebpage's 0.92 gate and the nightly actor need no change. `MODEL_MAP` gains one entry named `retype` (one
model id, one revision) that every label type may point at. `retype.api_fields` is a reference implementation, with tests.

## Follow-ups

- A second head for "misplaced or nothing there" against "wrong type". It needs the claimed type as an input (the
  same crop is correct for CurbRamp and incorrect for NoCurbRamp), so it is a different model family: a type
  embedding concatenated to the CLS token.
- Publishing: an 8-class model repo with `config.json` `id2label` in `retype.CLASSES` order, one confidence map per
  claimed type, and a card that states the complement loss. Not built; `publish_to_hf.py` is two-class.
- Surfacing the suggestion in Validate (SidewalkWebpage; #13's second checkbox).
- The 3 m merge across types (`--merge-radius-m 3`).
- The roughly 23,000 CurbRamp correct labels that round 3 downsampled away (`--cap-per-class` exists for a capped
  variant).

## Reproduce

```bash
# klone, repo root, logs/ present, the conda env active.
# 1. Login node (network): the labelEdits exports, from the live city list. retype_submit.sh refuses to start
#    without them, because a fetch on a compute node without network would kill the chain.
python retype.py fetch-edits --out /gscratch/scrubbed/$USER/retype-2026-11/retype-data/label_edits
# 2. One command submits the chain (extras, edits, crops, assemble, then per leg train, eval, report):
DATA=/gscratch/makelab/$USER/sidewalk-validator-ai/retrain-2026-10 RUNS=/gscratch/scrubbed/$USER/retype-2026-11 \
    PANO_STORE=<store or staged copy> ./retype_submit.sh
# One leg only:            LEGS=complement ./retype_submit.sh
# All four type edits:     EDIT_RAWLABELS=<fresh rawLabels pull> (the default snapshot joins two of four)
# 3. report reads the live /v3/api/cities. If the compute nodes cannot reach it, only the report job fails;
#    rerun it on a login node (minutes of CPU):
STEP=report LEG=complement JOB_IDS=<ids from retype_jobs.txt> DATA=... RUNS=... bash retype.slurm
# The audit on a Mac (aggregates only):
python retype.py audit --rawlabels <round-3 rawlabels> --splits <round-3 root> --edits <label_edits> \
    --out docs/retype-2026-11/audit.json
# After the report jobs: copy $RUNS/retype-data/docs-<leg>/ into docs/retype-2026-11/<leg>/ and fill the tables above.
```

Budget: about 1–3 GPU hours for the extra types, about 16 GPU hours per leg (12 epochs of about 42,000 train rows at
round 3's 1.4 it/s, plus validation; each train job has a 24 h limit, since a timeout is not requeued), about 1
hour of evaluation per leg: about 35 GPU hours for both legs on the free
`ckpt-all` partition. A preemption costs at most one epoch.
