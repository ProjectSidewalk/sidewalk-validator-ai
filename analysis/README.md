# Production analysis scripts

Scripts behind the October 2026 production measurements (`docs/calibration-2026-10.md`). They contain no data.
Their inputs and outputs include private-city labels, so keep them **outside the repo** (e.g. `~/Data/...`).

| script | what it does |
|---|---|
| `pull_ai_assessments.sh` | On the database host, read-only: one row per AI-assessed label across all city schemas (raw verdict, served accuracy, confidence, human votes excluding the AI, counted on the label's current type where the schema records it) → `ai_assessments.csv`. Optional `EXPERT1_ID`/`EXPERT2_ID` env vars add two validators' own votes. Since #52 also the model revision, training date and API version, whether the assessment cast a vote (`ai_vote_cast`), and the human votes of excluded validators. |
| `ai_disagree_census.sh` | On the database host, read-only: per city and label type, the SidewalkAI validator's Disagree votes, how many hide their label, how many it decided alone or by breaking a human tie, and how often the human majority agrees with it (SidewalkWebpage #5793). |
| `ai_disagree_to_unsure.sh` | On the database host: turns the AI's Disagree votes into Unsure and recomputes label counts/`correct` and the labelers' accuracy and `high_quality` with the app's own SQL. Read-only dry run by default (one row per city of what would change); `--apply --backup-dir <dir>` writes, one transaction per city, after backing up the vote rows. Runbook: [`docs/ai-disagree-reversal-2026-10.md`](../docs/ai-disagree-reversal-2026-10.md). |
| `analyze_calib.py` | Served accuracy vs observed human-majority agreement, gate pass rates, reliability bins, per-city precision, from `ai_assessments.csv` → `calib.txt`. |
| `fetch_all.py` | Downloads the public `rawLabels` CSV for every public city into a cache directory (tiling by bbox if an export truncates). `--label-types NoSidewalk,Signal` pulls only those types (one `labelType` export each) into the same `<city_id>.csv` layout and records them in `cities.json`. |
| `type_readiness.py`, `nosidewalk_pilot.py` | Issue #42. `type_readiness.py`: the training-data census for any label type from a rawLabels cache (label rule with and without `EXPERTS`, vote-pair histogram, block faces, the face rule as the 2026-11-05 census counted it and as `--verdict-unit face` applies it, tags, the NoSidewalk face-size prior) as aggregates only, private deployments pooled. `nosidewalk_pilot.py`: the pilot's crop arms x seeds (face-bootstrap AUC, within-city AUC, Agree gate at 0.92), spliced into the study page. Job files `../nosidewalk_pilot.slurm` / `../nosidewalk_submit.sh`. `nosidewalk_gate.py`: step (a), the 5-fold out-of-fold Agree gate over the pilot's whole-view crops (face-grouped folds, leave-one-fold-out calibration, the bar's Wilson bound), job files `../nosidewalk_gate.slurm` / `../nosidewalk_gate_submit.sh` (`KEEP_BEST=1` keeps each fold's best checkpoint). `nosidewalk_round.py`: step (b), the masked expert round outside Seattle: `pull` (fresh NoSidewalk rawLabels of the design's cities), `pool` (eligible labels and the seeded phase-1 sample to score), `build` (strata from the five fold models' gate verdicts, the phase-2 sample with inclusion weights, a `gt_rounds.py`-compatible key outside the repo) and `report` (the bar on the pass stratum, population-weighted rates, per city and per model, severity/tag slices), plus, for issue #102, `neighbours` (every other label on the rated faces, eligibility rules as flags, a run as `(face_id, labeler_idx)`) and `neighbour-scores` (their gate verdicts under the round's map, after checking that the map reproduces the pinned scores; aggregates only in the repo); design `gt_rounds/nosidewalk_b.json`, job file `../nosidewalk_round.slurm` (whole-view crops via `ai_labels_eval.py crops --fixed-crop-half-px 1024`, then one score per fold model). Results in [`docs/nosidewalk-2026-11.md`](../docs/nosidewalk-2026-11.md). |
| `nosidewalk_runs.py` | Issue #102, NoSidewalk runs (one labeler's labels on one block face). `step-a-neighbours` (every label on the step (a) faces, for one klone scoring job with the kept gate2 weights), `agreement` (item 1: within-run agreement of each label's own expert verdict, nulls within city and within labeler, strata by vote gap / page / same expert, all seven types; the run census), `pooling` (item 2: pooled image scores served through maps fitted on pooled scores of the same group, step (b) primary with the recommendation rule, step (a) out of fold), `features` (item 3: image-free neighbour features in a second-stage logistic model, step (a) leave-one-fold-out and frozen transfer to step (b)) and `report` (splices [`docs/nosidewalk-runs-2026-11.md`](../docs/nosidewalk-runs-2026-11.md)). User ids stay in memory; label rows go outside the repo; inputs pinned in `PINS`. |
| `ai_labels_eval.py`, `ai_labels_relabel.py` | AI-placed curb ramps: the round-3 CurbRamp validator scored on RampNet's labels in the three deployments that hold them, against the existing human votes (no new ground truth). Stages `select` (label set from rawLabels pulls, tier by submission campaign, round-3 train/val flag), `crops` (klone GPU: `data_generation.py`'s crop pipeline, untilted for rig-frame AI labels on every provider), `score` (`evaluate.run_inference` with one checkpoint), `report` (AUC with panorama bootstraps, the deployed gate's Agree coverage/precision and Disagree catch, slices by city, tier, vote count and reference, the human-placed round-3 test split as baseline). Job files `ai_labels_stage.slurm` / `ai_labels_gen.slurm`. `ai_labels_relabel.py` builds the masked Gallery re-label list for the labels the validator and a human disagreed about (labels the rater ever voted on left out; key outside the repo) and scores the rater's votes from a later rawLabels pull. Results in [`docs/ai-labels-2026-10.md`](../docs/ai-labels-2026-10.md). Since [#79](https://github.com/ProjectSidewalk/sidewalk-validator-ai/issues/79)/[#80](https://github.com/ProjectSidewalk/sidewalk-validator-ai/issues/80): `select --holdout` scores exactly the AI labels a `data_generation.py` run held out (training rule's class), `ablation` compares two checkpoints on them with a paired panorama bootstrap, `select --all-ai` keeps every AI label voted or not, and `ai_labels_relabel.py build --pool all --cap N --rank band_first` builds the ranked Disagree-only list, scored as a hit rate per tier, prior-vote status and rank bin ([`docs/ai-label-holdout-2026-11.md`](../docs/ai-label-holdout-2026-11.md)). |
| `analyze.py` | AI vs human majority (and vs expert validators given as `EXPERTS="name=user_id,..."`) from that cache → `analysis.txt`, `ai_vs_humans.csv`. Expert columns are always role-keyed `expert1`, `expert2`, … in `EXPERTS` order, whatever the names; `hard_examples.py` reads those names. |
| `calibration_doc_numbers.py` | Prints every figure in `docs/calibration-2026-10.md` that is not in `summary.md` (city mix, precision by vote count, pooled calibration error, confidence quantiles, model-swap window, NoCurbRamp drop, Triage what-if), from `calibrate_from_production`'s `labels_oof.csv`. Names public deployments only (`--cities-json`). |
| `routing.py` | Human–AI routing simulation (issue 18, `docs/routing-2026-10.md`): the AI decides a label when a score clears a threshold, humans decide the rest. Cost/accuracy curves per type for the calibrated, raw and old-map scores; per-verdict Pareto grid; the 0.92 operating points; single-human accuracy derived from vote counts; error-prediction AUC; expert complementarity (`--expert-cols`, role-keyed) and the ≥ 3-unanimous gold subset. Reads `labels_oof.csv` (+ `ai_assessments.csv`); names public deployments only (`--cities-json`). |
| `retrain_report.py` | The tables and figures of [`docs/retrain-2026-10.md`](../docs/retrain-2026-10.md), the round-3 retrain report: per type and split, AUC with panorama-resampled intervals, within-city AUC, per-deployment rows (public named, private pooled or lettered), the incorrect share per deployment, recall at precision and the hard slice from `metrics.json`, round 3 against the production validators on the 1,988-crop held-out sample (`vlm_baseline.py baseline` scores), the shipped calibration maps at the 0.92 gate (pooled-prior and own-mix precision, per deployment), a refit under `--alt-prior`, and the confidence saturation per type. Inputs: one run root with `<Type>/{predictions.csv,metrics.json,split.csv,calibration/}` and `deployment_priors.json`; public deployments from the live `/v3/api/cities` unless `--public-cities`; outputs under `docs/retrain-2026-10/`. |
| `road_prior.py` | Issue #45, first measurement: street-network / OSM prior for CurbRamp (driveway vs curb ramp). Stages `fetch-streets` (each public city's `/v3/api/streets` CSV; intersections = shared edge endpoints), `fetch-osm` (optional, Overpass: crossings and driveway ways), `features` (private label-level CSV; expert votes from `EXPERTS`), `evaluate` (per-feature AUC, leave-one-city-out lift over the production confidence, Disagree-vs-distance plots, Crosswalk check), `stratify` (far-from-intersection shares of the AI's verdict pools), `routing` (cast CurbRamp Disagrees by road context), `packet` (masked hand-coding packet, key outside the repo), `provenance` / `verify`; `road_prior_reproduce.sh` runs them all.
