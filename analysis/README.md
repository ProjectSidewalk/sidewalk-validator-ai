# Production analysis scripts

Scripts behind the October 2026 production measurements (`docs/calibration-2026-10.md`). They contain no data.
Their inputs and outputs include private-city labels, so keep them **outside the repo** (e.g. `~/Data/...`).

| script | what it does |
|---|---|
| `pull_ai_assessments.sh` | On the database host, read-only: one row per AI-assessed label across all city schemas (raw verdict, served accuracy, confidence, human votes excluding the AI) → `ai_assessments.csv`. Optional `EXPERT1_ID`/`EXPERT2_ID` env vars add two validators' own votes. |
| `ai_disagree_census.sh` | On the database host, read-only: per city and label type, the SidewalkAI validator's Disagree votes, how many hide their label, how many it decided alone or by breaking a human tie, and how often the human majority agrees with it (SidewalkWebpage #5793). |
| `ai_disagree_to_unsure.sh` | On the database host: turns the AI's Disagree votes into Unsure and recomputes label counts/`correct` and the labelers' accuracy and `high_quality` with the app's own SQL. Read-only dry run by default (one row per city of what would change); `--apply --backup-dir <dir>` writes, one transaction per city, after backing up the vote rows. Runbook: [`docs/ai-disagree-reversal-2026-10.md`](../docs/ai-disagree-reversal-2026-10.md). |
| `analyze_calib.py` | Served accuracy vs observed human-majority agreement, gate pass rates, reliability bins, per-city precision, from `ai_assessments.csv` → `calib.txt`. |
| `fetch_all.py` | Downloads the public `rawLabels` CSV for every public city into a cache directory (tiling by bbox if an export truncates). |
| `analyze.py` | AI vs human majority (and vs expert validators given as `EXPERTS="name=user_id,..."`) from that cache → `analysis.txt`, `ai_vs_humans.csv`. Expert columns are always role-keyed `expert1`, `expert2`, … in `EXPERTS` order, whatever the names; `hard_examples.py` reads those names. |
| `calibration_doc_numbers.py` | Prints every figure in `docs/calibration-2026-10.md` that is not in `summary.md` (city mix, precision by vote count, pooled calibration error, confidence quantiles, model-swap window, NoCurbRamp drop, Triage what-if), from `calibrate_from_production`'s `labels_oof.csv`. Names public deployments only (`--cities-json`). |
| `routing.py` | Human–AI routing simulation (issue 18, `docs/routing-2026-10.md`): the AI decides a label when a score clears a threshold, humans decide the rest. Cost/accuracy curves per type for the calibrated, raw and old-map scores; per-verdict Pareto grid; the 0.92 operating points; single-human accuracy derived from vote counts; error-prediction AUC; expert complementarity (`--expert-cols`, role-keyed) and the ≥ 3-unanimous gold subset. Reads `labels_oof.csv` (+ `ai_assessments.csv`); names public deployments only (`--cities-json`). |
| `retrain_report.py` | The tables and figures of [`docs/retrain-2026-10.md`](../docs/retrain-2026-10.md), the round-3 retrain report: per type and split, AUC with panorama-resampled intervals, within-city AUC, per-deployment rows (public named, private pooled or lettered), the incorrect share per deployment, recall at precision and the hard slice from `metrics.json`, round 3 against the production validators on the 1,988-crop held-out sample (`vlm_baseline.py baseline` scores), the shipped calibration maps at the 0.92 gate (pooled-prior and own-mix precision, per deployment), a refit under `--alt-prior`, and the confidence saturation per type. Inputs: one run root with `<Type>/{predictions.csv,metrics.json,split.csv,calibration/}` and `deployment_priors.json`; public deployments from the live `/v3/api/cities` unless `--public-cities`; outputs under `docs/retrain-2026-10/`. |
| `road_prior.py` | Issue #45, first measurement: street-network / OSM prior for CurbRamp (driveway vs curb ramp). Stages `fetch-streets` (each public city's `/v3/api/streets` CSV; intersections = shared edge endpoints), `fetch-osm` (optional, Overpass: crossings and driveway ways), `features` (private label-level CSV; expert votes from `EXPERTS`), `evaluate` (per-feature AUC, leave-one-city-out lift over the production confidence, Disagree-vs-distance plots, Crosswalk check), `stratify` (far-from-intersection shares of the AI's verdict pools), `routing` (cast CurbRamp Disagrees by road context), `packet` (masked hand-coding packet, key outside the repo), `provenance` / `verify`; `road_prior_reproduce.sh` runs them all. Results in [`docs/road-prior-2026-10.md`](../docs/road-prior-2026-10.md). |
| `vlm_baseline.py` | Issue #16: open-weight VLMs (MLX, on a Mac) as zero-shot validators on the round-3 held-out crops, against the five 2025-08 production DINOv2-L validators. Subcommands `score` (per-crop yes/no score from the next-token distribution), `baseline` (the 2025-08 production models; run from a venv with `requirements.txt` only), `timing` (batch-1 latency on an idle machine), `greedy` (greedy text vs score argmax), `report` (subset and full-sample tables, bootstraps, within-city AUC, ROC figure, provenance), `explain` and `packet` (masked two-pass explanation-rating packet, key outside the repo), `gallery` (adds the `rate.html` rating pages to a built packet), `agreement`. Results in [`docs/vlm-baseline-2026-10.md`](../docs/vlm-baseline-2026-10.md). Issue #63 adds the klone path: `score-torch` (one `TORCH_MODELS` leg, transformers bf16, batched with left padding and a batch-of-1 check, `--fewshot 8` for the in-context arm, resumable), `timing-torch` (batch-1 latency), `export-heldout` (held-out split slices and round-3 scores), `timing-summary`, and `baseline --split-root` (the 2025-08 models on every held-out crop); their outputs carry private-city label ids and stay outside the repo. |
| `vlm_score.slurm` | The klone launcher for issue #63: `MODEL=`, `TYPES=`, `VARIANT=`, `BATCH=`, `FEWSHOT=`, `LIMIT=`, `ENV=`, `MODE=score|timing|production`; defaults to the free `ckpt-all` partition with `--requeue` (resumes from the per-type CSV); runs offline from the scrubbed HF cache. Job log in [`docs/vlm-scoreboard/runs.md`](../docs/vlm-scoreboard/runs.md). |
| `vlm_vllm.py` | Issue #63, the vLLM leg: scores the round-3 held-out crops (test + test_heldout of `<Type>/split.csv`) with a VLM served by vLLM's OpenAI-compatible server, from the first generated token's top-20 log-probs (`max_tokens=1`, greedy), with `vlm_baseline.build_prompt` and `yes_no_score` so rows match the transformers path; adds `top20_mass_outside` (mass vLLM did not show) and `answer_floor` (a yes/no side absent from the top 20). `--prefill '<think></think>'` closes GLM-5.3-Flash's always-on think block. Subcommands `score` (resumable, `--concurrency` in flight, per-type CSV + meta with vLLM version, image tag, TP size and the rendered-prompt tail) and `timing` (concurrency 1, 10 crops per type). Standard library HTTP client; never imports vllm. Per-crop outputs carry `label_uid`s, so they stay outside the repo. |
| `vlm_vllm.slurm` | The klone job for `vlm_vllm.py`: starts `vllm serve` in the `vllm/vllm-openai` Apptainer image (default GLM-5.3-Flash, TP 4 on four H200s, ckpt with `--requeue`), waits for `/health`, runs the timing and score passes, stops the server. Model, types, limit, concurrency, prefill and template kwargs from the environment; caches and outputs on `/gscratch/scrubbed`. |
| `vlm_scoreboard.py` | Issue #63: the open-weight VLM scoreboard. `stage` fills a private staging directory (outside the repo: per-crop scores and held-out splits name private deployments) from the round-3 run and #16's Mac legs; the runner and vLLM legs write their score CSVs there too. `build` writes only aggregates to `docs/vlm-scoreboard/` (board, per-type AUC with label-bootstrap CIs, paired bootstraps against round 3, per public deployment with private pooled or lettered, coverage with the reason for every incomplete cell, timing and GPU-hours, AUC by label type × severity and × tag, pooled, per split and within-city, with crop and round-3 training counts), seven figures, provenance (sha256 of every staged file, the resolved public-deployment list), and splices the generated blocks of [`docs/vlm-scoreboard.md`](../docs/vlm-scoreboard.md). `build --check` fails on drift: full regeneration when the staging dir is present, else doc vs committed aggregates and prose counts (CI); both scan committed files for label keys and non-public deployment names. |
| `slices.py` | The standing severity × tag slice analysis (`docs/decisions.md`): per label type × severity and × tag (a label once per tag, `(none)` kept), n, AUC with panorama-bootstrap intervals, accuracy, training-row count with a `⚠ thin` flag, and a paired model-vs-baseline Δ per slice. Used by `evaluate.py` (on by default) and `retrain_report.py`. |
| `pull_relabel_pool.sh` | On the database host, read-only: one row per label the AI has voted on, across all city schemas (AI vote, latest served accuracy, severity, tags, pano view, human votes excluding the AI; optional `EXPERT1_ID`/`EXPERT2_ID` columns) → `relabel_pool.csv`. |
| `ai_disagree_relabel.py` | Masked expert re-label of the AI's Disagree votes (SidewalkWebpage#5793): `build` (stratified 300-item sample with decoys, crop check and fetch through one SSH master, `rate.html` packet, key outside the repo), `gallery` (per-deployment Gallery review lists for rating on the live site), `votes` / `comments` (the rater's prod votes and comments, sha256-pinned in the manifest), `prod-train` (the 2025-08 production training rows with severity and tags), `score` (AI precision against the expert, crowd vs expert), `report` (every aggregate behind the results, with training rows per severity and tag slice), `breakdown` (crowd confirmation by severity and tag). Results in [`docs/ai-disagree-relabel-2026-10.md`](../docs/ai-disagree-relabel-2026-10.md). |
| `gt_rounds.py` | Ground-truth rating rounds after round 1 (issue #78 and later): one city per rater with a shared overlap, designed from `gt_rounds/<round>.json`. Reuses `ai_disagree_relabel.py`'s pool pull (`SCHEMAS=...` restricts it), masking key, crop fetch, Gallery lists, vote pull and pins; adds strata that mark the AI Disagrees that are training rows under the margin rule (`margin_incorrect` / `margin_correct`) beside `lone` and `light_voted`, per-type quotas filled over severity buckets, `shared` items for inter-rater agreement, and `margin_class` / `round3_split` / both label-id forms in the key. Subcommands `build`, `gallery` (per rater, with the rating rule), `votes`, `score`, `agreement`. |
| `rating_page.py` | A self-contained HTML rating page (one card per image item, radio answers, notes, keyboard shortcuts, answers kept in the browser per rater) that exports a filled CSV sheet in the blank sheet's format; optional gate on a completed earlier sheet. Used by `vlm_baseline.py` for the `rate.html` pages. |
| `sidewalk_seg.py` | Issue #44, first experiment: sidewalk segmentation (Mask2Former, Mapillary Vistas) on the label-centred 2048² views of the round-3 held-out Obstacle / SurfaceProblem labels. Stages `filelist` (labels + store paths), `render-segment` (klone GPU job body: render as `data_generation.py` did, check the crop, segment), `coords` (pano coordinates from rawLabels), `features` (private per-label mask features), `cls` (frozen production pooled features on the Mac), `report` (aggregate tables, public cities named, private pooled), `sheets` (hand-check contact sheets, public cities only). Results in [`docs/segmentation-prior-2026-10.md`](../docs/segmentation-prior-2026-10.md). |
| `seg_prior_stage.slurm`, `seg_prior.slurm` | The two klone jobs for `sidewalk_seg.py`: stage the sample's panoramas from the pano store in one rsync connection (no requeue), then render + check + segment on one GPU. Both refuse to run outside the scrubbed scratch dir. |
| `serving_parity.py` | Issue #5: train/serve parity. Runs `data_generation.py`'s crop pipeline in a training venv and sidewalk-ai-api's real `/process` (Flask test client, recorders around depth and the validator) in the API's venv on the same panorama and points, then compares every stage: pano read, view render, depth, crop, WebP, preprocessing tensor, the five production validators' outputs and served votes. Stages `train-worker`, `api-worker` (`--pano-npy` cross-feeds the training pano), `compare`, `run`, `isolate`, `pixel-probe` / `pixel-compare` (opencv and WebP builds), `webp-sample` (second-generation WebP on the sampled crops), `crop-half`, `expected` (deploy smoke-test values), `figures`. Results in [`docs/serving-parity-2026-10.md`](../docs/serving-parity-2026-10.md). |

The maps themselves are fitted by `python -m calibration.calibrate_from_production` from `ai_assessments.csv`.
